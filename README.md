# SPRESENSE + STS3032（SoftwareSerial 版）

SPRESENSE の拡張基板と秋月電子の STS 用 MAX485 回路で、STS3032 を動かすサンプルです。

- 拡張基板 D2 ← 回路 RXD（MAX485 RO）
- 拡張基板 D4 → 回路 TXD（MAX485 DI）
- サーボ ID：1、通信速度：**115200 bps**
- モニター：115200 bps（SPRESENSE メイン基板の USB）

サーボ側の通信速度も、あらかじめ 115200 bps に設定してください。この設定はサーボに保存されます。工場出荷時の 1 Mbps のサーボでは、そのままでは通信できません。また、この設定に変更したサーボを 1 Mbps のプログラムで使う場合は、サーボ側の速度を 1 Mbps に戻す必要があります。

起動時にトルクを有効にし、中央位置 2048 へ移動します。その後、中央から左右それぞれ約15度の位置（1877 と 2219）を、往復3秒で繰り返します。加減速度の設定値は50、速度の設定値は500です。現在は送信専用で、サーボの位置やエラーは表示・監視しません。

```sh
pio run
pio run -t upload
pio device monitor -b 115200
```

## 調査メモ：受信待機と往復時の動作

- 6 Vでの比較では、往復中に軸から約1 cmの位置に指で負荷をかけると、SoftwareSerial の受信待機が有効な場合は止まりやすく、`stopListening()` で無効にすると強く動きました。位置の問い合わせを行わず受信待機だけを有効にしても、弱くなりました。保持位置を指で押した場合は動きませんでした。
- サーボから読み取った最大トルク設定と現在のトルク上限はともに1000（100%）でした。過負荷保護は有効で、しきい値80%、時間2秒、保護時の保持トルク20%でした。負荷中の保護状態は確実に取得できていません。
- 受信待機が影響する状況は再現しましたが、受信割り込みが送信タイミングやサーボにどう影響するかは未解明です。位置読み取り処理はコメントアウトして残し、受信割り込みを無効にしています。受信を再開する際は動作と通信を再検証してください。
- この回路と実機では、受信応答の最初のヘッダー `FF` が `FE` になる場合がありました。保存した読み取り処理は2番目の `FF` 以降を検証しますが、先頭ヘッダーの完全性は検証できません。

STS3032 の仕様上の電源電圧は4〜7.4 Vです。過去の8.4 Vでの確認では、サーボが報告する電圧は約8.0〜8.1 V、設定上の電圧上限は9.0 Vでした。この設定値は製品の定格上限を示すものではありません。
